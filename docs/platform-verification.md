# 平台上传与人工播放验证

本文规定如何从“本地导出成功”走到“上传入口/草稿”，再到“发布/转码分发”，最后到“真实设备上观察到的实际显示”。它不是平台官方文档，也不能替代平台规则；平台入口、审核与转码策略随时可能变化。

## 1. 验证阶段必须分开

| 阶段 | 需要什么证据 | 不能用什么代替 |
| --- | --- | --- |
| **导出成功** | `smoothup verify` 与 `ffprobe` 显示文件可完整解码、帧率/时长/音频符合预期；记录文件 SHA256。 | 终端出现“完成”、文件存在、播放器能打开。 |
| **上传入口** | 平台页面显示文件接收完成，或保存为草稿；记录文件 SHA256、页面提示、时间。 | 本地导出成功、上传进度截图、草稿本身。 |
| **发布/转码分发** | 公开投稿成功，出现稿件 URL/审核状态，平台完成转码与分发。 | “上传完成”、草稿保存、开放 API 返回 `video_id` 但未发布。 |
| **实际显示** | 在指定设备、客户端版本、显示刷新率下，用慢动作录像/逐帧检查测得目标帧率，并检查音画同步。 | 平台清晰度标签（如“1080P60”）、主观“看起来更流畅”、上传或发布成功本身。 |

当前两平台测试作品已发布并完成网页分发流与浏览器帧计数测量：同一份 SmoothUp 640×360、60fps 成品均分发为 30fps；B 站原生 1080p120 样片的“1080P 60帧”档分发为 60fps、浏览器实测约 59.96fps，本次未见 120fps 档。完整结果见第 8.1 节；手机 App、物理屏幕显示和音画同步仍未测量。

## 3. 验证前：固定本地证据

对每个待上传文件执行并留档：

```powershell
$file = '.\sample-60fps.mp4'
Get-FileHash -Algorithm SHA256 $file
.\smoothup.exe verify $file --fps 60 --json --verbose | Tee-Object .\verify.json
.\smoothup.exe inspect $file --json | Tee-Object .\inspect.json
```

再用 `ffprobe` 记录精确流信息（把路径替换为实际 `ffprobe.exe`）：

```powershell
ffprobe -v error -show_entries stream=index,codec_type,codec_name,width,height,pix_fmt,avg_frame_rate,r_frame_rate,duration,nb_frames -show_entries format=duration,size -of json $file
```

记录：

- 源文件与输出文件的 SHA256、字节数、生成时间。
- `avg_frame_rate` / `r_frame_rate` 是否为 `60/1`、`120/1`、`60000/1001` 或 `120000/1001`。
- 视频时长、音频时长、音频流是否存在。
- `smoothup verify` 的 JSON 结果。
- 使用的引擎（`auto` 实际选了 CPU 还是 RIFE）、是否用了 `--preview`。

这些只证明“导出成功”。

## 4. 生成可判读的测试样片

源码仓库提供 `scripts/generate-samples.ps1`（不进入发布 ZIP），生成 30/60/120fps 三个带以下特征的样片：

- 每帧都有递增帧号，便于慢动作录像后数唯一帧。
- 每 2 秒硬切场景，检验插帧不会把切换处“融化”。
- 每秒有音频提示音，画面同步闪烁；切点有双重提示，便于检查音画偏移。
- 默认输出到 `.work/samples/`，不会提交到仓库。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\generate-samples.ps1

# 本次实际记录使用的 4 秒 1080p 参数
powershell -ExecutionPolicy Bypass -File .\scripts\generate-samples.ps1 -Seconds 4 -Width 1920 -Height 1080
```

需要已有 FFmpeg/FFprobe；脚本支持 `-Ffmpeg`、`-Ffprobe` 参数，或读取 `SMOOTHUP_FFMPEG` / `SMOOTHUP_FFPROBE`。生成后可先用 `smoothup verify` 确认 30/60/120 三个文件本身正确，再上传。样片只用于技术验证，不要使用未授权的影视/音乐素材。

2. 选择与实际相符的投稿类型（自制/转载）；测试样片应标为自制或按平台规则处理。

## 6. 播放测量

### 6.1 设备与设置

- 至少一台支持 120Hz 刷新率的手机用于 120fps 测试；60Hz 屏幕无法证明 120fps 播放。
- 关闭设备的“运动补偿/MEMC/视频增强/插帧”类功能。否则你看到的是电视或手机补帧，不是平台输出。
- 关闭省电模式与自动亮度；固定屏幕亮度，避免录像曝光变化。
- 用支架固定拍摄设备，让屏幕占满画面；不要手持。
- 优先使用手机慢动作（120/240fps）录制平台播放画面；记录拍摄帧率。

### 6.2 帧率判读

样片画面左上/中央有递增帧号。播放样片，用慢动作录制至少 3 秒，然后逐帧查看：

1. 选取一段连续 1.0 秒的播放时间（可用画面中的秒提示或音轨对齐）。
2. 统计这 1 秒内出现的**唯一帧号数量**，而不是录像帧数。
3. 重复 3 次，取中位数。

参考判读：

| 源样片 | 若播放为 30fps | 若播放为 60fps | 若播放为 120fps |
| --- | --- | --- | --- |
| 30fps 样片 | 约 30 个唯一帧号/秒 | 不会超过源（通常 30） | 不会超过源 |
| 60fps 样片 | 约 30 个唯一帧号/秒（帧号跳变） | 约 60 个唯一帧号/秒 | 60 个左右（若被限 60） |
| 120fps 样片 | 约 30 个 | 约 60 个 | 约 120 个 |

注意：

- 平台播放器可能暂停、缓冲或 UI 叠加，统计时避开这些区间。
- 显示刷新率低于目标帧率时，唯一帧号会明显少于源帧率；这只能证明“该设备/该档位未观察到”，不能证明平台对所有人都降帧。
- 平台清晰度标签是辅助证据，不是帧率证据；标签写“60”仍应实测。
- 若平台提供“原画/下载”且下载文件可被 `ffprobe` 读取，可记录下载文件的 `avg_frame_rate`；但下载档位也可能与在线播放不同，需注明。

### 6.3 音画同步

样片每秒有短提示音与画面闪烁，切点有双重提示：

1. 用慢动作录像同时拍到画面与听到的声音（或录屏带系统声音）。
2. 找到画面闪烁帧与音频波形起点。
3. 以录像帧率换算偏移：240fps 录像每帧约 4.17ms；120fps 录像每帧约 8.33ms。
4. 建议记录：≤40ms 可接受；40–100ms 需复查；>100ms 视为明显偏移并记录为问题。

这不是平台官方容差，只是本项目的人工验收参考。若偏移明显，先检查本地 `verify` 与源文件，再判断是否平台转码造成。

### 6.4 场景切换

样片每 2 秒硬切。逐帧检查切点前后：

- 是否出现整帧“融化/重影/黑帧”。
- 切点后的第一帧是否属于新场景。
- 切点处音频是否与画面同时切换。

这检验插帧的场景保护；与平台帧率结论分开记录。
