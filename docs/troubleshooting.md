# 故障排查

先收集事实，再改参数。推荐顺序：

```powershell
.\smoothup.exe doctor --verbose
.\smoothup.exe inspect .\问题文件.mp4 --json
.\smoothup.exe verify .\问题文件.mp4 --json --verbose
```

`doctor` 看依赖，`inspect` 看容器/流，`verify` 做完整解码与时序检查。不要只凭播放器“能打开”判断文件正确。

## 1. 找不到 FFmpeg / FFprobe

现象：启动转换即报缺少 `ffmpeg` 或 `ffprobe`，或 `doctor` 显示不可用。

- 运行 `smoothup setup`，让程序安装固定版本到当前用户管理目录。
- 已有可信 FFmpeg 时，显式设置：

```powershell
$env:SMOOTHUP_FFMPEG = 'D:\tools\ffmpeg\bin\ffmpeg.exe'
$env:SMOOTHUP_FFPROBE = 'D:\tools\ffmpeg\bin\ffprobe.exe'
.\smoothup.exe doctor --verbose
```

- 显式环境变量指向不存在的文件时会直接报错，不会静默改用 PATH。这是有意的：避免“以为用了 A，实际用了 B”。
- 不要从随机网盘下载 `ffmpeg.exe` 后改名为系统文件；优先使用 `setup` 的固定版本与 SHA256，或可信发行版。
- 若公司代理导致下载失败，先配置系统代理或在可联网环境执行 `setup`，再把管理目录整体复制到目标机器；复制后运行 `doctor` 验证。

## 2. `setup` 失败 / SHA256 不匹配

- 校验失败通常意味着下载被代理替换、截断或上游文件变化。删除失败的部分，重试；不要跳过校验。
- 安装是增量式的：已有可用组件不会因为新增 RIFE 失败而被删除。修复网络后重试即可。
- 权限错误：确认对 `SMOOTHUP_HOME`（默认当前用户目录下的管理目录）有写权限；不需要管理员权限。
- 磁盘不足：FFmpeg ZIP 约 114.8 MB，解压后占用更大；RIFE ZIP 约 431.5 MB，但只保留约 17 MiB 的引擎、DLL 与 v4.6 模型。预留足够临时空间。
- 参数 `setup --rife` 只安装一个模型（v4.6），不要手工把其他模型塞进管理目录来“试试”；`doctor` 会显示实际模型路径。

## 3. RIFE / Vulkan 不可用

现象：`--engine rife` 报错；或 `auto` 使用了 CPU，速度慢。

- `--engine rife` 失败是预期行为：它不会静默降级到 CPU。先用 `--engine cpu` 完成导出，再排查 GPU。
- 更新显卡驱动；确认显卡支持 Vulkan。集成显卡也可用，但显存/内存不足时可能失败。
- 运行 `smoothup doctor --verbose` 查看探测到的 RIFE 引擎、模型与 GPU。
- 关闭占用 GPU 的游戏/录屏/浏览器硬件加速后重试。
- 显式路径：

```powershell
$env:SMOOTHUP_RIFE = "$env:LOCALAPPDATA\SmoothUp\deps\rife\rife-ncnn-vulkan.exe"
$env:SMOOTHUP_RIFE_MODEL = "$env:LOCALAPPDATA\SmoothUp\deps\rife\rife-v4.6"
.\smoothup.exe doctor --verbose
```

实际管理目录以 `doctor` 输出为准，不要照抄示例路径。

- RIFE 处理长视频会分块；如果中途失败，先确认磁盘与内存充足，再缩短预览验证。不要用 `--fps` 之外的方式伪造插帧。

## 4. 输出文件相关

### 已存在输出 / 拒绝覆盖

```text
输出文件已存在；使用 --overwrite 允许替换输出
```

- 默认不覆盖任何既有输出。确认路径后加 `--overwrite`；它只允许替换输出，不会允许覆盖源文件。
- 即使 `--output` 指向输入文件，程序也会拒绝。请换输出路径。

### 文件被占用

- 关闭正在播放该文件的播放器、资源管理器预览、同步盘、杀毒扫描。
- 输出先写临时文件，成功后才替换；如果目标被占用，替换阶段会失败并保留原文件。
- 不要同时运行两个转换写同一个输出路径。

### 磁盘空间 / 路径过长

- 4K 高帧率输出可能很大；先用 `--preview 10` 估算体积。
- 路径接近 260 字符时，启用 Windows 长路径支持或改用更短的目录。
- 路径包含空格、`&`、括号、中文时，用引号包住整个路径；在 PowerShell 中把参数作为数组传给程序最稳妥。

### 失败后留下 `.partial` / `.tmp`

正常取消或失败会清理临时文件；进程被强杀、断电或杀毒软件拦截时可能残留。确认没有转换在运行后，删除同目录下对应输出的临时文件即可，不要删除源文件。

## 5. 媒体兼容性与画质

### 源是可变帧率（VFR）

手机录屏、直播录制常见 VFR。表现为时长对但运动抖动、音画逐渐漂移。先转成恒定帧率再处理，或直接用 `smoothup verify` 检查输出时序。不要用“播放器看起来正常”代替时序检查。

### 旋转、SAR、奇数尺寸

- 手机竖拍视频可能带旋转元数据。程序按旋转/SAR 归一化，并把尺寸补到偶数，避免 H.264 的奇数尺寸问题。
- 不会为了“适配平台”强制裁剪或放大；画幅与源一致。平台端如何展示由平台决定。

### HDR / 10-bit / 色彩

- 输出固定为 SDR、8-bit、yuv420p。HDR 源会做实际色调映射，颜色不会与 HDR 原片逐像素一致。
- 如果源是 HLG/PQ，先确认播放器/平台对 SDR 输出的预期；不要把“颜色变淡”直接当成 bug。
- 不支持把 HDR 只改标签冒充 SDR；如果看到此类行为，应视为缺陷。

### 音频

- 输出 AAC，保留源音频时序与起始偏移；不会用 `-shortest` 掩盖音画长度问题。
- 多音轨源是否全部保留取决于当前实现的映射策略；需要多语言版本时先分离处理，并用 `inspect` 检查输出音轨。
- 源无音频时输出无音频，`verify` 不会凭空要求音频。
- 音画偏移明显时，先用 `ffprobe` 比较源与输出的音频起始时间、时长，再判断是源、容器 edit list 还是平台转码造成。

### 插帧伪影

- 快速运动、遮挡、字幕、闪光、镜头切换处可能出现重影/融化。先用 `--preview` 找问题片段。
- 场景切换由场景检测保护；仍建议人工检查切点。
- 源帧率已经不低于目标时不会做无意义插帧；不要期待“再插一遍”提升流畅度。
- `--quality high` 更慢、文件更大，但不保证消除所有伪影。

### 输出时长变短 / 尾部丢失

- 这是高 stakes 缺陷。`smoothup verify` 会在发布前检查完整解码与时序；失败时不会把半成品当成功输出。
- 若仍怀疑，比较源与输出的 `format.duration`、视频/音频流 `duration` 与 `nb_frames`，并检查最后 1 秒是否有画面/声音。
- 不要用 `-shortest`、`-t` 之类的外部命令“修补”后当作 SmoothUp 的输出。

## 6. 平台侧问题

### 上传被拒 / 处理失败

- 核对平台当前的格式、大小、时长、分辨率要求；抖音开放平台文档与网页入口的限制可能不同。
- 确认文件没有被其他程序占用，且本地 `verify` 通过。
- 平台审核/版权/内容规则不属于 SmoothUp 能修复的范围。
- 记录平台错误码与提示；不要把平台拒绝误报为本地导出失败。

### 发布后播放不流畅 / 看起来只有 30fps

- 先按 [平台上传与人工播放验证](platform-verification.md) 测量唯一帧号，不要只凭感觉。
- 平台可能转码降帧；账号权益、客户端版本、清晰度档位、网络与设备刷新率都会影响结果。
- 60Hz 屏幕无法展示 120fps；关闭电视/手机的 MEMC/视频增强，否则看到的是设备补帧。
- 本地 `ffprobe` 显示 60/120fps 只证明文件正确；平台播放结论需要单独证据。
- 若平台下载档可获取，检查下载文件的 `avg_frame_rate`，但注意下载档不一定等于在线播放档。

### 清晰度标签显示 60，但不确定是否真 60

清晰度标签不是帧率证据。按验证文档用慢动作录像数唯一帧号；无法测量就写“未验证”。

## 7. Windows / PowerShell

- 执行随包脚本时若提示执行策略限制：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

- 路径含 `&` 时不要直接拼接命令行字符串；使用引号或参数数组。
- PowerShell 5.1 默认编码可能影响中文日志；需要机器可读结果时优先 `--json`。
- 发布包未签名，SmartScreen/杀毒可能提示。用 SHA256 核对来源；企业环境按组织策略加白名单。
- 若使用动态链接 MSVC CRT 的本地构建，可能缺少 `VCRUNTIME140.dll`；安装 Microsoft Visual C++ 2015–2022 可再发行组件，或使用 CI 的静态 CRT 发布构建。GNU 工具链构建的依赖不同，按实际报错处理。

## 8. 退出状态与取消

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `0` | 成功 | 继续本地验证/上传流程。 |
| `1` | 参数、依赖、媒体、验证或写出失败 | 看 stderr 首条“错误：”；加 `--verbose` 复现。 |
| `130` | Ctrl+C 取消 | 确认临时文件已清理；重新运行。 |

取消会尽快终止子进程并清理临时输出；操作系统或驱动卡死时可能延迟。不要在同一输出上立即启动第二个进程。

## 9. 提交问题时应附带的材料

- `smoothup --version`、`doctor --verbose` 输出。
- 完整命令（隐去个人路径与账号信息）。
- `inspect` / `verify --json` 结果。
- 源与输出的 `ffprobe` JSON、文件大小、SHA256。
- 出错时间点与是否可复现；不要上传包含隐私/版权内容的原片，必要时用生成的测试样片复现。
- **不要**附带 access token、Cookie、平台账号密码或未打码的个人信息。
